## Finding

**Medium — workspace-specific session validation can reject a valid session when a user has multiple memberships in one tenant.** `IdentityProviderImpl.validate_session` calls `get_by_id_for_tenant(user_id, tenant_id)`, then compares the one returned membership’s workspace with the session workspace ([provider.py](../../packages/identity/src/rick_identity/provider.py#L131), [provider.py](../../packages/identity/src/rick_identity/provider.py#L151)). The PostgreSQL tenant lookup has no workspace predicate and uses `LIMIT 1` ([postgres.py](../../packages/identity/src/rick_identity/postgres.py#L323)). Where a user has active memberships in two workspaces under the same tenant, selecting the other valid membership makes the caller’s session anonymous. The integration fixture creates this same-tenant, two-workspace state ([test_migrate.py](../../infrastructure/scripts/tests/test_migrate.py#L1264)), but does not validate a bearer for each membership. Current tests prove mismatch rejection, not that both valid workspace sessions remain accepted. No unauthorized session acceptance was demonstrated; the evidenced risk is false rejection.
