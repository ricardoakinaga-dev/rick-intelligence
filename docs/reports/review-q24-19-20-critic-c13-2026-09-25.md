## C12 finding corrected

`admin_update_user` now takes the global account row lock before loading the exact tenant/workspace projection on every PATCH, including an empty or unchanged-workspace-only PATCH ([`postgres_identity.py`](../../apps/api/src/services/postgres_identity.py#L587)). It then saves the full account projection under that same transaction. Password recovery acquires the global account lock before locking the exact membership and updating credentials ([`postgres_identity.py`, recovery](../../apps/api/src/services/postgres_identity.py#L852)); the full-row upsert writes `password_hash` and `password_version` ([`postgres.py`](../../packages/identity/src/rick_identity/postgres.py#L513)). The shared lock prevents a stale admin projection from restoring credentials after recovery.

The real PostgreSQL regression pauses an empty PATCH after the membership read, starts recovery, confirms that recovery waits for the account lock, and then verifies the recovered password and version remain current. The recorded pre-fix run failed because recovery passed the paused PATCH; the post-fix run passed ([test](../../infrastructure/scripts/tests/test_migrate.py#L1922), [pre-fix log](evidence/implementation-q24-2026-09-24/verification-q24-20260925T1132Z-c9-fix/c13-sparse-recovery-before-fix.log#L97), [post-fix log](evidence/implementation-q24-2026-09-24/verification-q24-20260925T1132Z-c9-fix/c13-sparse-recovery-fixed.log#L1)).
