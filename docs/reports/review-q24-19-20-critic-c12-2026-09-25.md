## High-severity finding: sparse admin update can restore an old password

In [`admin_update_user`](../../apps/api/src/services/postgres_identity.py#L608), the global account lock is conditional on `email`, `role`, collection IDs, or permission overrides. An empty PATCH or one carrying only an unchanged `workspace_id` bypasses that lock and keeps the user projection read before the update ([lines 614–627](../../apps/api/src/services/postgres_identity.py#L614)). The workspace value can pass its unchanged-value check, and the method still saves the record ([lines 648–660](../../apps/api/src/services/postgres_identity.py#L648)).

The identity store's upsert writes `password_hash` and `password_version` from that full record on conflict ([`postgres.py`, lines 513–523](../../packages/identity/src/rick_identity/postgres.py#L513)). If the sparse PATCH reads first, password recovery then locks the account and exact membership, commits a new password and revokes sessions, and the PATCH saves afterward, the stale values can restore the previous password ([recovery lock/update](../../apps/api/src/services/postgres_identity.py#L885)). Recovery's transaction does not serialize with this sparse path because the PATCH skipped the same global row lock. Sessions revoked by recovery remain revoked, but the former password can become valid again.

The listed real-PostgreSQL concurrency regression covers recovery against membership deactivation ([`test_migrate.py`, lines 1379–1429](../../infrastructure/scripts/tests/test_migrate.py#L1379)); it does not exercise recovery racing an empty or workspace-only admin update. Criterion 8 is therefore PARTIAL. The correction should serialize every full-row administrative write with credential recovery before loading the row, then re-resolve the actor's exact membership, or use a narrowly scoped update that cannot write credential columns. Add a live PostgreSQL interleaving regression that pauses after the sparse update reads, commits recovery, resumes the update, and asserts the recovered hash/version remain authoritative.
